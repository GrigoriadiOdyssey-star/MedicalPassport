# Изменения EDHT

Репозиторий содержит спецификации. Предложение не получает статус «реализовано» без кода, проверок и доказательств приёмки.

1. Найдите исходные ID в [реестре](docs/module-index.md) и проверьте [дубликаты](data/duplicates.json).
2. Для новой функции заполните [шаблон спецификации](docs/templates/feature-specification.md). Укажите границы, зависимости, владельцев по ролям, модель данных, негативные сценарии, источники и критерии приёмки.
3. Меняйте нормативные разделы в `docs/product`, `docs/engineering`, `docs/safety` и контракты в `specs`. Исправления исходных формулировок оформляйте точными заменами в `config/editorial-corrections.json`, с исходным ID и причиной. Исходный текст в `sources` сохраняется.
4. Выполните `npm run build`, `npm test`, `npm run check` на Node.js 24. Зависимости npm не требуются. Изменения с медицинским назначением проходят проверку ответственного клинического специалиста; требования приватности — ответственного за обработку данных.
5. Откройте merge request с описанием результата и доказательствами. Не добавляйте реальные медицинские данные, ключи, пароли или токены в примеры, логи и Git.

Сгенерированные `docs/product-bible.md`, `docs/modules`, `docs/module-index.md` и `data` изменяются только генератором. Заголовки с одинаковым названием не объединяются без анализа предметной области; при объединении сохраняются alias исходных ID и журнал решения.
