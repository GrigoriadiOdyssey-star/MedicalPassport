# MASTER19 control: existing Twin and Precision Pharmacology

This addendum extends CAP-TWIN and CAP-CDS. CAP-MEDICATION remains exposure/reconciliation truth; it does not acquire pharmacology inference ownership. Existing MASTER08 requirements already contain the requested anatomy, dynamic organism, PGx, molecular context, research-release and canonical ingestion capabilities. The control matrix links exact requirement anchors rather than inventing additional modules. Architecture coverage is not implemented or clinically validated functionality.

## Shared snapshot and direct integration contract

The authoritative path is external source → CAP-INTEROP staged validation/mapping → appropriate clinical source owner in the canonical EDHT data layer → authorized immutable context snapshot → CAP-CDS precision assessment → CAP-TWIN scenario → versioned prediction/risk/uncertainty → clinician decision support. Direct external feeds into a clinical scenario are prohibited. CAP-AI executes models and records execution provenance; Knowledge/Clinical/Personal AI are role/task profiles of that owner, not alternative truth stores. Laboratory supplies genetics/PGx and biomarker results; Protein Intelligence supplies attributed derived molecular evidence. Neither a predicted protein structure nor a population association proves a patient drug response.

Context includes available age/date basis, clinically relevant sex context, weight/height/BSA with units/formula/time, diagnoses/comorbidities, allergies/adverse reactions, medicines/supplements/history/exposure, renal/hepatic measurements and equations, laboratory/biomarkers, pregnancy/lactation, pediatric development, genomic/PGx/proteomic/metabolomic results, phenotype and prior response. Each input records PRESENT, UNKNOWN, NOT_TESTED, ABSENT or CONFLICTING plus source/version/time; an absent value never becomes zero or normal. A model's versioned input requirements determine abstention, rather than requiring every possible omics test for every case. No dose formula or clinical threshold is supplied by this architecture pass.

Typed handoff fields: tenant_reference, patient_reference, purpose, context_reference, context_version, context_sha256, source_manifest_reference, exposure_reference, disease_state_reference, device_state_reference (nullable), evidence_release_reference/version, model_reference/version, profile_reference/version, created_at_ms, horizon_ms, assumptions_reference, uncertainty (method and reference, or explicit UNKNOWN), result_reference/version, epistemic_status, validity_state and clinician_review_reference (nullable). Every opaque reference resolves only through the existing authorized owner. Reference equality alone does not authenticate a subject. The source manifest must contain the exact source identity/version/hash/unit/time used, including missingness and transformations.

CDS owns AssessmentRequest/AssessmentResult and review disposition; Twin owns ScenarioRun and Overlay references. requestMedicationAssessment validates authorized context and evidence/model applicability; compareTherapyScenarios creates separately identified hypothetical runs with the same baseline; recordClinicianReview binds reviewer and exact result/context/evidence versions. Same idempotency key plus identical bound input returns the existing job; changed input returns CONFLICT. STALE_CONTEXT, UNSUPPORTED_PROFILE, INSUFFICIENT_EVIDENCE, UNAPPROVED_RELEASE and AUTHORIZATION_DENIED produce no synthetic clinical result. Review never creates an order. Prescribing, dose change and discontinuation require independent human-authored clinical workflows.

Source corrections, withdrawn access, changed exposure and suspended model/evidence releases invalidate dependent outputs using source-manifest reverse references. Mark derived history INVALIDATED; never overwrite its input history or return it as current. Recalculation creates a new result version. Concurrent invalidation before authorized release blocks the response; after release, display an update warning on subsequent authorized views, without claiming to recall delivered information. At-least-once invalidation events deduplicate by event ID and source version; out-of-order events cannot reactivate invalidated results.

## Anatomy, dynamic organism and evidence labels

Twin Core owns patient-specific and longitudinal state, physiological/organ/system/disease models, risk forecasts, treatment-response scenarios and specialty projections. GENERIC_ANATOMY references an atlas release and stays labelled generic even when shown beside patient data. PATIENT_DERIVED_ANATOMY additionally requires verified patient/study/series/frame references, accepted segmentation/registration version, coordinate system/transforms, derivation evidence and qualified acceptance. CT, MRI, PET/CT, X-ray, ultrasound and OCT are supported as source categories, not a claim of implemented connectors or a guarantee of 3D reconstruction. A 2D X-ray or missing acquisition geometry cannot be represented as proven volumetric patient anatomy. Unsupported modalities remain unavailable and keep a text/report view.

Dynamic organism overlays preserve organ/system/pathway, laboratory/biomarker, disease activity and therapy exposure links. Keep OBSERVED, MEASURED, CLINICIAN_ASSESSED, INFERRED, PREDICTED and SIMULATED visible on every value, timeline, tooltip and export; REPORTED remains available for patient-reported context. Clinical validation state is separate from epistemic status. Selecting a drug creates a hypothetical comparison only. A simulated organ/pathway effect never writes Observation, Condition, medication order or delivered exposure. Unknown effect is labelled unknown, never green/zero. Time alignment, uncertainty and stale/missing intervals remain visible, with keyboard/text/table alternatives carrying the same warnings.

## Evidence release and privacy

Research pattern → hypothesis → methodologically appropriate validation → independently authorized evidence release → versioned Knowledge layer → separately applicable CDS/Twin model release. A hypothesis or unapproved population correlation is rejected at the clinical boundary. Evidence release binds protocol/dataset/method versions, claim, limitations, population applicability, review identity and expiry/review triggers. Signed release syntax is not genuine approval proof; actual trust/approver integration remains required. Genomic/family and reproductive data obey source segmentation; scenario permission never permits copying relatives' records.

## Acceptance and remaining work

Architecture tests must verify that all requested capabilities have source anchors, reference the existing owners, preserve required provenance fields and reject simulation-to-fact promotion. Negative scenarios cover mismatched patient, unapproved research evidence, generic anatomy relabeling, source correction, absent uncertainty, unsupported population and attempted prescribing. These are design/contract tests, not numerical model validation.

Missing deployment capabilities: implemented and qualified model families; licensed/versioned evidence and terminology packs; real imaging/device connectors; imaging derivation acceptance; calibrated intended-use performance; clinician comprehension/accessibility testing; runtime authorization/invalidation/replay evidence. Their absence blocks clinical use. No new conceptual capability or canonical owner is required for the MASTER19 checklist; detailed model-specific schemas and numerical acceptance criteria remain engineering/clinical work under the existing owners.
