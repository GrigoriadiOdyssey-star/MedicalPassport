# Правила API P0

Статус: **proposed-specification**. Машинный контракт: [OpenAPI 3.1.1](../../specs/openapi.json). Исходные модули: 7, 8, 10, 12, 14, 27, 29, 30, 32, 33, 53–59, 81–84, 89. API пока не реализован.

## Общий контракт

Пути относительны к /api/v1 будущего HTTPS-сервиса. Все endpoints, кроме POST /qr-resolve, требуют проверенного access token владельца; этот единственный endpoint авторизует ограниченный bearer-секрет тела запроса. UUID не даёт права доступа. Субъект из тела запроса не принимается. Повседневный доступ поддержки к медицинским данным отсутствует.

Все успешные и ошибочные ответы имеют Cache-Control: no-store и серверный X-Request-Id. Медицинские значения, filenames, cookies, QR и access tokens не попадают в URL, метрики и логи. Прямой JSON-объект без success/data envelope. Ошибки — application/problem+json: type, title, status, code, request_id и необязательный безопасный detail. Это применение [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html); stacktrace и медицинские значения не включаются. Структура машинного описания основана на [OpenAPI 3.1.1](https://spec.openapis.org/oas/v3.1.1.html).

Тела запросов закрыты для неизвестных полей. PUT — полная замена изменяемых полей; null очищает необязательное значение. Server IDs, provenance, versions и timestamps не принимаются от клиента. Profile/Allergy/Medicine/Document возвращают ETag; замена и удаление требуют If-Match с одной сильной версией в кавычках. Отсутствие —428, несовпадение —412.

Создающие POST требуют Idempotency-Key 16–128 ASCII символов и хранят сопоставление 24 часа; тот же ключ/субъект/операция/тело возвращает исходный ресурс и исходный код, другое тело —409. QR-секрет имеет специально указанное исключение. Revoke POST без тела повторяемы и сохраняют исходное revoked_at. Multipart принимает ровно один файл; нет автоматического OCR или клинической верификации.

Пагинация: limit 1–100, по умолчанию 50; items и next_cursor (null в конце). Курсор непрозрачен, подписан/проверен сервером, связан с владельцем, маршрутом и последним (created_at,id); для audit — (occurred_at,id). Порядок по возрастанию. Страницы не являются замороженным снимком: созданные записи могут появиться на следующих страницах, удалённые исчезнуть. Экспорт использует отдельный согласованный снимок. Чужой или неверный cursor —400 без данных.

400 —синтаксис/параметры; 401 —access token; 403 —состояние аккаунта/повторный вход; 404 —отсутствующий или чужой ID (также унифицированный отказ QR); 409 —бизнес-инвариант/состояние/idempotency; 410 —истёкший export; 413 —размер; 415 —media type; 422 —схема/семантика; 429 —лимит с Retry-After; 500 —неожиданная ошибка; 503 —недоступна обязательная зависимость или audit. Отказ в авторизации проверяется прежде чем раскрывать состояние ресурса.

## Уточнения операций

### createProfile

Профиль допускается только для согласованной взрослой аудитории. Возраст и birth_date проверяет реализация; в будущем —422. Начальный allergy_status recorded недопустим до появления активной аллергии (409). Второй профиль →409.

### replaceProfile

Проверяются allergy_status и наличие активных аллергий; несовместимое состояние →409. Null очищает необязательное значение. Поля request body обязательны; частичная замена не поддерживается. Удаление всего паспорта — через account/deletion.

### createAllergy

Профиль должен существовать. Создание активной аллергии атомарно меняет allergy_status профиля на recorded и увеличивает его version.

### replaceAllergy

Изменение clinical_status синхронно согласует allergy_status профиля. При исчезновении последней активной аллергии профиль становится unknown.

### deleteAllergy

Удаление последней активной аллергии переводит allergy_status в unknown, увеличивая version профиля. Повторный DELETE возвращает 404.

### createMedicine

Профиль должен существовать. end_date не раньше start_date; нарушение →422. Сведения о дозе внесены пользователем, API не рассчитывает дозировки.

### replaceMedicine

Полная замена всех изменяемых полей. end_date >= start_date, если обе даты заданы; нарушение →422.

### deleteMedicine

Повторный DELETE возвращает 404; физическая очистка по утверждённой политике.

### uploadDocument

Один файл PDF/JPEG/PNG 1–20 MiB; размер всего multipart ≤21 MiB. MIME определяется по содержимому. Профиль должен существовать. Идемпотентность сравнивает title, реальный MIME, размер и SHA-256 байтов; filename не определяет storage_key. Poll GET metadata до available/rejected; до available скачивание запрещено.

### downloadDocument

quarantined или rejected →409 document_unavailable. deleted и чужой ID →404. Range-запросы P0 не поддерживает; файл выдаётся целиком. Нет редиректа на публичный URL.

### createConsent

Профиль должен существовать. notice_version должна быть опубликованной текущей версией показанного текста; неизвестная/устаревшая версия →409 notice_version_unavailable. Разрешение не подтверждает личность получателя и не устанавливает все правовые основания обработки. Без согласия QR не создаётся.

### revokeConsent

Без request body. Идемпотентно. В одной транзакции блокирует consent и отзывает grants. Уже выданные копии не отзываются.

### createQrGrant

Согласие активно, принадлежит владельцу, scope grant — подмножество consent. expires_at не позднее consent; нарушение →409. Секрет: 32 CSPRNG байта, base64url без padding, только digest в БД. Повтор Idempotency-Key с тем же телом →409 qr_secret_already_issued с grant ID в безопасном detail; новое тело с тем же ключом →409 idempotency_conflict. Потерянный секрет не восстанавливается; grant можно отозвать и создать новый.

### revokeQrGrant

Без request body. Идемпотентно, не требует знать QR-секрет. Уже выданные копии удалить невозможно.

### resolveQr

Единственная операция без owner access token: авторизация через непредсказуемый секрет request body. Никогда не принимает token в URL. Unknown/expired/revoked/consumed возвращают одинаковый 404 qr_unavailable. Конкурентное использование даёт ровно один 200. После commit и потери ответа повтор запрещён. Если активных аллергий или лекарств >100 в выбранном разделе →409 snapshot_too_large, без consumption. При недоступности audit или БД →503, выдачи нет. Тело запросов/ответов и секрет нельзя писать в логи.

### listAuditEvents

Сортировка occurred_at,id. Идентификаторы actor другого человека, IP и секреты не возвращаются владельцу. Чтение истории пишется в технический security event, не создавая рекурсивный медицинский read-event.

### createExport

Без request body. Профиль должен существовать. Не более одного активного export; конфликт →409. ZIP содержит согласованный JSON, доступные файлы и manifest с причинами отсутствия остальных. Идемпотентный повтор возвращает исходный job.

### downloadExport

pending/running/failed →409 export_unavailable. Истёкший результат →410 export_expired. Результат хранится 24 часа после completed_at. Account deletion запрещает скачивание сразу.

### requestDeletion

Требуется подтверждённый auth_time ≤5 мин; иначе 403 reauthentication_required. До конца удаления разрешён только getDeletion. Повтор исходного запроса с тем же ключом разрешён в deletion_pending и возвращает исходный job. Не следует объявлять физическое удаление завершённым до очистки и учёта retention.

### getDeletion

Доступ разрешён субъекту, создавшему deletion job, также в deletion_pending/deleted; для этого сохраняется минимальное соответствие job–subject на утверждённый период. Полная медицинская запись не сохраняется ради статуса. Чужой/несуществующий job →404.

## Границы проверки

JSON, внутренние ссылки, параметры путей, уникальность operationId, модель security и синтетические schema-примеры проверяются локально. Такая проверка не доказывает поведение сервера и не заменяет полноценный OpenAPI-validator, интеграционные тесты или проверку безопасности реализации. Все операционные инварианты (владелец, дата, гонки, expiry, отзыв, аудирование) требуют серверных тестов при реализации.
