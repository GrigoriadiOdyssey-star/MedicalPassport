# Patient receipt query — missing-field addendum, MASTER-18

Extends CORE-CAP-AUDIT and the adult, single-allergy-record disclosure slice. No clinical payload, audit export, investigation search, representative access, emergency override or new endpoint is introduced. This is a contract and a synthetic conformance oracle, not an implemented service or evidence of authenticated approval. Full-owner readiness remains blocked.

## Operation, authority and ownership

GET /v1/disclosure-grants/{grant_id}/receipts is the existing proposed route. Query parameters are limit (integer 1–100, default 25) and optional opaque cursor. Unknown/duplicate parameters and malformed identifiers return 400 INVALID_REQUEST. The server obtains tenant, adult patient identity and current patient-account binding from verified Identity/Security adapters, never query parameters or caller-supplied patient IDs. A clinician grant to read an allergy record grants no permission to read the patient's receipts. Administrators, clinics, pharmacy/laboratory services, caregivers and reviewers have no access through this route. Investigation/export authorization remains outside scope.

Require current authenticated patient binding, current `audit.receipts.read_self` policy decision for that tenant and that grant's patient, and an available verified audit store. The grant's ACTIVE, REVOKED or EXPIRED state does not itself determine the patient's right to inspect past access; revocation prevents further clinician access, not the patient's historical accountability view. Patient-account access suspension or a denial from Security still blocks the query. A tombstoned grant retains an authorized patient-to-audit binding under approved retention; missing binding cannot be guessed from a receipt ID.

Audit owns immutable durable receipt references, projection sequence and operation/outcome metadata. Consent owns the grant-to-patient binding and lifecycle. Identity owns current adult patient binding; Security owns live authorization; Data owns retention policy selection. No audit body, raw clinical values, token, actor name, email, source document, IP address or before/after change payload is returned. `actor_reference` is an opaque patient-scoped reference where disclosure is authorized, otherwise null; null is not an unknown unauthorized actor classification. Actor role codes are PATIENT, CLINICIAN, SERVICE or WITHHELD. No claim of a comprehensive audit history can be made outside the returned snapshot.

## Closed response and chronology

`specs/audit-receipt-query18.schema.json` defines version 1. Success is 200 with exactly kind, schema_version, grant_reference, snapshot_sequence, items and next_cursor. Each item has receipt_reference, receipt_sequence, occurred_at_ms, committed_at_ms, action, outcome, actor_role and actor_reference. The patient projection sequence is monotonic within this tenant/grant projection; it is not the tenant-wide internal ingestion sequence, which would expose activity in other grants. Gaps are permitted after policy-authorized withholding/retention and do not imply missing clinical actions. Duplicate receipt IDs/sequences and descending sequence order are rejected. No sequence may exceed snapshot_sequence. Producer occurrence timestamps may precede or exceed committed timestamps because of clock skew; order uses committed projection sequence, never patient-controlled time.

Actions are GRANT_CREATED, GRANT_REVOKED, GRANT_EXPIRED, ALLERGY_VIEW_ATTEMPT and RECEIPTS_VIEW. Outcomes are COMMITTED, DENIED, UNAVAILABLE. COMMITTED for a view means the controlled access-attempt audit commit occurred; it does not prove network delivery, screen display or that a clinician read or understood the content. Lifecycle events require COMMITTED; access attempts retain their actual outcome. This wording avoids incorrectly relabeling a pre-disclosure durable append as proof of successful disclosure.

Cursor is a random, opaque, short-lived server-side reference; the contract default is 5 minutes (engineering lifetime, not legal retention). Bind it to authenticated patient, tenant, grant, snapshot upper bound, last returned sequence, policy version, selected projection version and effective limit. Do not encode clinical or identity data into the public cursor. Each request reauthorizes; a valid cursor is not a permission token. Wrong binding, tampering, expiration, changed policy or unavailable snapshot returns 400 INVALID_CURSOR without exposing its former target. Cursor creation and random lookup must be protected against guessing, bounded in storage and redacted from access logs.

Stable snapshot paging uses the same upper sequence and strictly increasing position; new events after snapshot creation appear only on a new query. Authorization tightening applies immediately and invalidates the cursor. Approved deletion or changed redaction affecting that snapshot invalidates it; do not retain previously exposed fields just to preserve paging. Empty first page has items=[] and next_cursor=null. A nonnull next_cursor requires at least one returned item and known further permitted items; do not emit empty progress loops. There is no total count or bulk export. Retention may make old receipts unavailable; an empty result must not be interpreted as proof that no access ever occurred.

## Errors, failure and self-audit

401 UNAUTHENTICATED for absent/invalid authentication. For authenticated callers, inaccessible and nonexistent grant references return the same 404 NOT_FOUND response shape, without distinguishing wrong tenant, clinician-only permission or absent resource. An internally unavailable policy/audit adapter returns 503 UNAVAILABLE with no partial body; rate limit returns 429 RATE_LIMITED. Error envelopes contain only kind, schema_version, code and request_reference. Use Cache-Control: no-store; no cacheable redirect, ETag or embedded route/token in diagnostic messages. Error code mapping is tested as a contract, not a constant-time security proof.

Before returning any successful page, append one authorized RECEIPTS_VIEW audit event with the selected snapshot and result count through the existing internal append boundary; do not include returned content or cursor. If durable append fails, fail closed with 503. This internal append does not call the public query route and cannot recursively generate receipt queries. Its sequence is greater than the captured snapshot and appears only in a later fresh query. Rate-limited/denied attempts enter appropriately protected security telemetry; prevent attacker-driven unbounded event amplification.

Retries are side-effect-free with respect to grant/clinical state, but may produce separately identified query-attempt events. This endpoint does not promise exactly-once auditing of HTTP retries. Audit append itself retains the MASTER-16 idempotency contract per attempt. Restore must reconcile patient/grant projection positions with durable source receipts before serving; projections rebuilt from unverified logs are unavailable. Expired cursors are discarded after restore, never accepted against a different sequence epoch. No legal duration or deletion approval is supplied here.

## Exchange, observability and acceptance

This patient-facing internal projection has no FHIR export in this slice. An external AuditEvent mapping is a separate full-owner requirement and needs versioned semantic-loss fixtures; internal JSON validity does not claim FHIR conformance. Version 1 rejects unknown fields/actions; incompatible changes require a new version plus compatibility fixtures. Redacted-change and legacy-import envelopes remain blocked.

Measure bounded aggregate query latency, authorization/unavailable counts, invalid-cursor counts, projection lag and append failure rate; do not label metrics by patient, tenant, grant, receipt or cursor. Proposed load acceptance: p99 query response <= 1 second with <=100 returned items at an explicitly agreed load; no performance evidence is claimed. Numeric operational load, named incident owner and real log-redaction testing remain open.

Synthetic tests cover closed syntax, pagination/order/uniqueness, lifecycle semantics, denied/missing equivalence, actor withholding and bounds. Required runtime acceptance: independently authenticated patient bindings; cross-tenant/clinician denial; concurrent role revocation between authorization and response; policy-change cursor rejection; crash after audit commit; projection rebuild and sequence-epoch handling; absence of sensitive values in logs/cache; absence of recursive audit; whole-journey UI distinguishes attempt from delivered/read data. Security/Privacy/Architecture must approve the concrete store/adapters and patient-visible actor policy; clinical reviewer must accept the non-delivery wording. These evidence gates are not satisfied by this document.
