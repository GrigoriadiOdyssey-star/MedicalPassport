# CORE-CAP-IDENTITY — consolidated source profiles

Uses an existing registered canonical owner and preserves all prior addenda. All owners already have canonical specifications. Every clause below applies only to its listed source profiles; it is not a universal clinical rule. No new service, clinical approval or implementation readiness.

## provider-directory-profiles

Existing Identity owns provider/organization directory identities and separately verified credential references. Search/rating/price/language fields remain attributed directory metadata; ranking and listing do not attest licensure, quality, availability or clinical eligibility.

Acceptance additions: Preserve organization/branch identity, location, specialty, language, rating source/time and verification state. Expired credentials and stale directory fields must not be presented as current authorization. Booking and clinical acceptance remain separate operations.

## identity-authentication-profiles

Existing Identity owns authentication, verified account/role and credential lifecycle references. Security owns resource/purpose enforcement; professional titles and device biometric factors do not automatically grant patient access. Source IAM breadth is decomposed by these existing responsibilities.

Acceptance additions: Preserve patient/professional/service roles, credential and MFA lifecycle, recovery/expiry/revocation and source verification. Never store raw biometric data or infer patient identity from an account ID; require current issuer, binding and misuse-case evidence before activation.
